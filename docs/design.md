# Intake
MIT-licensed local-first medicine and alcohol journal. Empty initial catalog: users explicitly configure their own names, colors, units, default quantities and presets. Phone-first interface with concise functional labels and no promotional filler or decorative asterisks. Always-visible Today totals, one-tap logging with optional pre-entry note and backdate. Edit/delete/undo, per-item elapsed time, configurable day boundary and timezone, daily notes, explicit zero days, seven-day history, import preview and export (real .xls, JSON backup). Never infer missing logs as abstinence. No medical advice or default substances.

## Contract
One FastAPI server serves built frontend and SQLite under CONFIG_DIR (/config). Basic auth remains supported on journal /api endpoints. The app exchanges Basic credentials through POST /api/session for a random 30-day HttpOnly, SameSite=Strict browser cookie scoped to /api (Secure when PUBLIC_ORIGIN or the request uses HTTPS); signup also establishes this session. SQLite stores only token hashes and expiration, and POST /api/logout revokes this browser's session. Passwords are never saved in browser storage. Cookie authentication requires the app's custom request header; journal requests carry the expected immutable account ID to reject another tab's account switch before reading or writing data. Restore identity through GET /api/me on startup and reconnect, then automatically drain the local queue. Missing/expired sessions never discard pending entries or open a native Basic dialog. Registration status and signup are public with first-user bootstrap, closed subsequent registration by default, and persistent abuse throttling. Generic static shell public to permit offline launch. Hash passwords using scrypt, no default credentials. Create the first account through the app; additional registration requires ALLOW_SIGNUP=true or the interactive operator CLI. Dark purple interface with readable contrast. Local cached last profile can log offline; first use/account switches require verified online identity. Account-scoped IndexedDB data. No CDN, analytics or external runtime requests.

GET /api/me returns {id,username,settings:{timezone,day_start}}. POST /api/sync receives {operations:[{id,entity:'item'|'entry'|'day',record_id,base_version:0|integer,data:object,deleted:false|true}],cursor:integer}. Responds {results:[{id,status:'applied'|'conflict'|'invalid',record?:object,message?:string}],changes:[record],cursor:integer,has_more:boolean}. Records are {id,entity,version,deleted,data}. Each operation transaction atomically writes record, receipt and monotonic change log. Same operation ID/different payload is rejected. IDs UUIDs. Ownership comes exclusively from auth. Change pagination 500 records. Revision conflicts return server record, never overwrite. Invalid operations remain locally recoverable. Item data: name,color (#hex),unit,amount (positive numeric),presets (positive numeric array),archived (boolean),order (integer). Entry data: item_id,quantity,unit,item_name,color,occurred_at (ISO offset timestamp),timezone,note. Day data: date YYYY-MM-DD,note,zero (boolean). Settings update through PUT /api/settings {timezone,day_start} (online only), day_start integer 0..23. Quantity decimal precision retained; snapshots preserve historical units/name. Server validates all payloads, referential ownership, size limits. Archived items cannot invalidate pending historic entries.

Client serializes reactive UI values to plain JSON wire data before persistence. A local transaction writes materialized record and outbox together before acknowledging. Per-user serialized sync, ordered operations with revisions; preserve optimistic changes during remote pulls. Conflicts preserve local copy and offer keep local/use server. Request persistent storage. Do not claim cross-device freshness offline. Sync on launch/resume/reconnect/edit and bounded retries while open, closed-app best effort. A persistent top banner shows all pending local changes, including conflicts and invalid operations, until a successful sync completes with an empty outbox; a durable account-scoped sync-needed marker keeps the banner marked Sync incomplete across reloads and sign-ins after a failed later pull, even after writes were acknowledged. The marker is written atomically with local edits and only cleared by full successful sync when no newer local operations remain. It shares a sticky region with Today totals and provides Sync now, progress and failure status; signed-out retries open the in-app sign-in without discarding local changes. Cached shell/service worker; clear-cache upgrades do not clear database. Explicit import previews JSON backups and CSV mapping with invalid/ambiguous rows flagged, no arbitrary code. XLS export includes pending local records, backend POST /api/export accepts bounded snapshot {items,entries,days}; returns real BIFF8 workbook, strings never interpreted as formulas. XLS generation uses xlwt; offline export has clear needs-server message; JSON backup works offline.

## History views
History provides Week, Timeline, By item and Calendar views with shared inclusive date-range and item filters. Default week starts Monday; previous/next navigate the active period. Calendar uses full months. Weekly small-multiple charts switch between entry count and quantity, keeping each medicine and historical snapshot unit separate. Timeline places entries at exact local clock times relative to the configured day boundary, preserves repeated DST instants and uses separate lanes for collisions. By item shows period entry count, days with recorded entries, separate quantity totals, median interval between recorded entries and an editable entry list. Month cells distinguish recorded use, confirmed global zero days, unlogged days and days outside the selected range. Filtering never infers a zero day. All calculations consume materialized account-local records, including pending edits and archived/orphan historical items, and respect timezone/day-start settings. Today totals stay visible. Tapping a chart day opens daily history; tapping an entry opens its existing editor. History component state resets on account change. No server round trips, chart dependencies, data schema or authentication changes.

## Deployment
Docker Compose app with localhost binding by default. Networking and reverse proxies are operator-managed. /config local disk includes database, settings and consistent online backup CLI. Non-root app, writable /config, healthcheck, same-origin API, strict CSP, origin checking for mutating requests, request body limits, private no-store API responses, persistent auth throttle. Timezone/day-boundary calculation shared frontend logic with midnight/DST tests. Desktop/mobile keyboard, focus and reduced motion support.
